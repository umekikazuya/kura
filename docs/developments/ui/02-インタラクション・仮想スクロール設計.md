# 02. インタラクション・仮想スクロール設計

> React ベースのコンポーネント構成、Vim スタイルのキーボード操作、および仮想スクロールによるパフォーマンス最適化の設計を定義する。

---

## 1. コンポーネントと責務

```text
<KuraApp>           # ルート（キーボードイベントのグローバルリスナーを配置）
├── <SearchInput>   # 検索クエリの入力と表示
└── <ClipList>      # 仮想スクロールコンテナ
    └── <ClipItem>  # 各クリップの描画 (テキスト制限、画像サムネイル等)
```

---

## 2. フォーカスとキーボード操作 (Vim スタイル)

kura は完全なキーボード操作を前提とし、洗練された「Vim にインスパイアされた操作体系」を採用する。

### 2.1 フォーカスの基本方針

- ウィンドウを開いた直後、**フォーカスはリスト（`<ClipList>`）** にある（ノーマルモード）。
- リストにフォーカスがある状態で通常の文字キーを入力しても **何も起きない**（誤爆防止・状態の保護）。
- 検索を開始する場合は、**`/` (スラッシュ) キー** を押して検索モードに入る（画面下部などにコマンドライン風の入力欄がアクティブになる）。

### 2.2 キーバインディング

| 状態                        | キー入力        | アクション                                                                           |
| :-------------------------- | :-------------- | :----------------------------------------------------------------------------------- |
| **リストフォーカス時**      | `j` / `↓`       | 選択行を1つ下に移動 (`selectedIndex++`)                                              |
|                             | `k` / `↑`       | 選択行を1つ上に移動 (`selectedIndex--`)                                              |
|                             | `/`             | 検索モードに入る                                                                     |
|                             | `Enter`         | 選択中のアイテムをペースト (IPC: `PasteItem`)                                        |
|                             | `Cmd+Backspace` | 選択中のアイテムを削除 (IPC: `DeleteItem`)                                           |
| **検索モード（`/`入力中）** | 文字入力        | `query` を更新し、リアルタイムに IPC: `SearchClips` を発行                           |
|                             | `Esc`           | 検索モードをキャンセルし、入力中のクエリを破棄してノーマルモード（リスト操作）に戻る |
|                             | `Enter`         | 検索を確定し、ノーマルモード（リスト操作）に戻る (選択行は先頭)                      |
| **グローバル**              | `Cmd+W` / `Esc` | アプリケーションウィンドウを非表示にする                                             |
|                             | `Cmd+Q`         | アプリケーションを完全に終了する                                                     |

## 3. 仮想スクロールとレンダリング最適化

### 3.1 仮想スクロールの仕組み

数万件の履歴が存在しても、DOM にマウントされる `<ClipItem>` は**可視範囲 ＋ 上下バッファ（合計 20〜30 ノード）のみ**に制限する。
React エコシステムのデファクト標準である `@tanstack/react-virtual` を採用する。

**高さの固定化による最適化**:
テキストや画像などアイテムの種類によらず、**`<ClipItem>` の高さは CSS で 72px に完全固定**する。これにより動的計測（`measureElement`）のオーバーヘッドとスクロール時のガタつき（Jitter）を完全に排除し、極めて高速なレンダリングを実現する。

```typescript
// 実装イメージ (TanStack Virtual)
const rowVirtualizer = useVirtualizer({
  count: items.length,
  getScrollElement: () => parentRef.current,
  estimateSize: () => 72, // 1アイテムの固定高さ目安 (px)
  overscan: 5, // 上下のバッファ数
});
```

### 3.2 選択状態とスクロールの連動

`j` / `k` によるインデックス移動時、選択されたアイテムが可視範囲外に出た場合は、`rowVirtualizer.scrollToIndex(selectedIndex)` を呼び出して自動的にスクロールを追従させる。

### 3.3 アニメーションと GPU 活用

スクロールコンテナには `will-change: transform` を適用し、GPU コンポジティングを強制する。
また、選択行のハイライト移動には CSS トランジション（`transition: transform` など）を用い、常駐アプリとして極めて滑らかな操作感を実現する。
