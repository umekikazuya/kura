# 01. ドメインモデル

> **本ドキュメントはストレージ技術・UIフレームワーク・OS API に依存しない。**
> kura のコアドメインである「クリップボード記録の管理と活用」の
> 集約・値オブジェクト・Factory・Repository・ドメインサービスを定義する。

---

## 0. ユビキタス言語

| 用語                                  | 定義                                                                                              |
| :------------------------------------ | :------------------------------------------------------------------------------------------------ |
| **クリップ (Clip)**                   | クリップボードにコピーされた1件の記録。テキスト・画像・ファイルのいずれかの型を持つ               |
| **クリップ履歴 (Clip History)**       | 過去に記録されたクリップの時系列コレクション                                                      |
| **コンテンツ (Content)**              | クリップが保持する実際のデータ。最大サイズの制約を持つ値                                          |
| **コンテンツハッシュ (Content Hash)** | コンテンツから一意に導出される指紋。重複記録の防止に使用する                                      |
| **ピン留め (Pin)**                    | クリップを自動削除ポリシーの対象外として固定すること                                              |
| **再コピー (Re-copy)**                | 既に記録済みのコンテンツが再びコピーされること。タイムスタンプの更新のみが発生する                |
| **ソースアプリ (Source App)**         | コピー操作を行ったアプリケーション。Bundle ID と名前で識別する                                    |
| **除外アプリ (Blocked App)**          | ユーザーが記録対象外として設定したアプリケーション。SourceApp が自身の Bundle ID を用いて判定する |
| **ペースト (Paste)**                  | 選択したクリップを直前のアクティブアプリケーションに送信すること                                  |

---

## 1. コアドメインと境界づけられたコンテキスト

### 1.1 コアドメイン

kura のコアドメインを **「クリップボード記録の管理と活用」** と定義する。
ユーザーがクリップを選択してペーストするというアウトカムは、
履歴の蓄積・保護・高速な検索という前工程によって成立する。
この一連のプロセス全体がコアドメインであり、分割に意味はない。

### 1.2 境界づけられたコンテキスト

```text
┌────────────────────────────────────────────────┐
│  クリップ管理コンテキスト（Core Domain）       │
│                                                │
│  ClipItem, ClipItemFactory,                    │
│  ClipItemRepository (interface),               │
│  SourceApp（IsBlocked を持つ値オブジェクト）    │
└────────────────────────────────────────────────┘
            ↑ blockedBundleIds をアプリケーション層経由で受け取る
┌───────────────────────────────────────────────────┐
│  設定コンテキスト（Supporting Domain）            │
│                                                   │
│  AppConfig（除外アプリ・最大件数・ショートカット）│
└───────────────────────────────────────────────────┘

┌────────────────────────────────────────────────┐
│  インフラストラクチャ（Generic / Technical）   │
│                                                │
│  NSPasteboard 監視（ConcealedType 除外を含む）, │
│  SQLite 実装, CGEvent ペースト, Wails IPC      │
└────────────────────────────────────────────────┘
```

**設計方針**: コアドメインはインフラと設定コンテキストに依存しない。
設定値（`blockedBundleIds` 等）はアプリケーション層が受け取り、ドメインオブジェクトのメソッドに渡す。
FTS5・SQLite・NSPasteboard・ConcealedType はコアドメインの語彙に登場しない。
ConcealedType の除外はインフラ層（NSPasteboard 監視）が担い、ドメインに届く前に棄却する。

## 2. 集約

kura のコアドメインには集約が **1つ** 存在する: **ClipItem**。

### 2.1 ClipItem（集約ルート）

ClipItem は集約ルートかつ唯一のエンティティである。
集約内の他のメンバーはすべて値オブジェクトであり、ルート経由でのみアクセスされる。

#### 2.1.1 集約境界と不変条件

ClipItem 集約が守る不変条件:

| 不変条件                                                             | 根拠                                                  |
| :------------------------------------------------------------------- | :---------------------------------------------------- |
| `contentHash` は `content` から一意に導出され、生成後に変更されない  | 重複検出の信頼性の担保                                |
| `isPinned` の状態遷移は `Pin()` / `Unpin()` メソッドのみから行われる | 集約ルートによる状態管理の独占                        |
| `content` のサイズは `clipType` ごとの上限以内である                 | Factory が保証し、集約は有効な Content のみを受け取る |

**境界の外側**にあるもの（集約が知らないこと）:

- データをどこに永続化するか → `ClipItemRepository` 実装
- FTS インデックスの存在 → リポジトリ実装の内部

#### 2.1.2 エンティティ構造

```text
ClipItem（集約ルート・エンティティ）
├── id: ClipItemId          [値オブジェクト] 集約全体の同一性を表す
├── content: Content        [値オブジェクト] 不変。生成後に変更されない
├── contentHash: ContentHash [値オブジェクト] 不変。content から導出
├── clipType: ClipType      [値オブジェクト] text | image | file
├── sourceApp: SourceApp?   [値オブジェクト] nil = ソース不明
├── isPinned: bool          集約が管理する状態（デフォルト: false）
├── createdAt: Timestamp    [値オブジェクト] 不変。生成時に確定
└── updatedAt: Timestamp    [値オブジェクト] 再コピー時のみ更新
```

#### 2.1.3 ライフサイクル

```text
【生成フェーズ】
  ClipItemFactory.NewClipItem(rawContent, clipType, sourceApp)
       ↓
  (1) コンテンツ切り詰め + サイズ検証
  (2) ContentHash の算出
  (3) ClipItemId の採番（UUID v7）
  (4) createdAt / updatedAt = 現在時刻
  (5) 有効な ClipItem インスタンスを返す（この時点ではまだ永続化されていない）

【再構成フェーズ】  ← 生成と明確に区別する
  ClipItemRepository.FindByID(id) / FindByHash(hash)
       ↓
  DB に永続化済みのデータから ClipItem を復元する
  （バリデーションは再実行しない。DB に保存された時点で有効性は保証済み）

【活動フェーズ】
  ┌─ Pin()             isPinned: false → true（前提条件違反で error を返す）
  ├─ Unpin()           isPinned: true → false（前提条件違反で error を返す）
  └─ RefreshTimestamp() updatedAt を現在時刻に更新（再コピー時にアプリケーション層が呼ぶ）

【削除フェーズ】
  ClipItemRepository.Delete(id)
       ↓
  集約はリポジトリに削除を委譲する。集約自身は削除処理を知らない。
```

#### 2.1.4 メソッド定義

| メソッド           | シグネチャ           | 前提条件            | 副作用             |
| :----------------- | :------------------- | :------------------ | :----------------- |
| `Pin`              | `Pin() error`        | `isPinned == false` | `isPinned = true`  |
| `Unpin`            | `Unpin() error`      | `isPinned == true`  | `isPinned = false` |
| `RefreshTimestamp` | `RefreshTimestamp()` | なし                | `updatedAt = now`  |

> **設計判断**: `create()` と `upsert()` はメソッドとして存在しない。
> 生成は Factory が、再コピー時の判断（新規か既存かの分岐）はアプリケーション層が担う。
> 集約は自分が DB に存在するかを知らない。

## 3. 値オブジェクト

| 値オブジェクト | 型                                   | 不変条件・振る舞い                                                |
| :------------- | :----------------------------------- | :---------------------------------------------------------------- |
| `ClipItemId`   | UUID v7 (string)                     | UUID フォーマット準拠。ソートで時刻順になる                       |
| `Content`      | `{ raw []byte; truncated bool }`     | サイズは text ≤ 5MB / image ≤ 20MB                                |
| `ContentHash`  | string (SHA-256 hex)                 | 64文字の16進数。Content から決定論的に導出                        |
| `ClipType`     | enum                                 | `text` \| `image` \| `file` のいずれか                            |
| `SourceApp`    | `{ bundleId BundleId; name string }` | BundleId は reverse-DNS 形式。`IsBlocked([]BundleId) bool` を持つ |
| `BundleId`     | string                               | reverse-DNS 形式（例: `com.apple.Safari`）                        |
| `Timestamp`    | int64                                | UNIX epoch 秒                                                     |

### SourceApp の振る舞い

```go
// SourceApp は「自身の Bundle ID が除外リストに含まれるか」を判定できる。
// 除外リストはアプリケーション層が設定コンテキストから受け取り、このメソッドに渡す。
// SourceApp 自身は設定コンテキストを知らない。
func (s SourceApp) IsBlocked(blockedBundleIds []BundleId) bool

// sourceApp が nil（ソース不明）の場合はアプリケーション層で記録を許容する。
// SourceApp が存在する場合のみ IsBlocked を呼ぶ。
```

## 4. Factory

```go
// domain/factory/clip_item_factory.go

// NewClipItem は有効な ClipItem を生成する唯一の経路である。
// - コンテンツのサイズ検証と切り詰めを行う
// - ContentHash を算出する
// - ClipItemId を採番する
// 生成された ClipItem はまだ永続化されていない（Repository.Save が必要）。
func NewClipItem(
    rawContent []byte,
    clipType   ClipType,
    sourceApp  *SourceApp,
) (*ClipItem, error)
```

**Factory の責務**:

- `rawContent` を受け取り、`ClipType` に応じたサイズ上限を適用して切り詰め
- `Content` 値オブジェクトの構築（`truncated` フラグを設定）
- `ContentHash`（SHA-256）の計算
- `ClipItemId`（UUID v7）の採番
- 有効な `ClipItem` の返却

## 5. Repository インターフェース

```go
// domain/repository/clip_item_repository.go
// ※ このファイルはインターフェース定義のみ。実装はインフラ層に置く。

type ClipItemRepository interface {
    // 再構成: ID による単件取得
    FindByID(id ClipItemId) (*ClipItem, error)

    // 再構成: ContentHash による単件取得（重複チェック用）
    FindByHash(hash ContentHash) (*ClipItem, error)

    // 再構成: 最新順での一覧取得（空クエリ時のデフォルト表示）
    FindRecent(limit int) ([]*ClipItem, error)

    // 再構成: 全文検索による取得（検索キーワードの解釈はインフラに委ねる）
    Search(query string, limit int) ([]*ClipItem, error)

    // 保存: 新規 ClipItem の永続化（INSERT）
    // および既存 ClipItem の状態変更の反映（UPDATE）
    Save(item *ClipItem) error

    // 削除: 物理削除
    Delete(id ClipItemId) error
}
```

**設計上の重要な判断**:

- `Search()` のシグネチャに FTS5・trigram・SQLite の言葉は登場しない
- `Save()` が INSERT と UPDATE を兼ねる（コレクションへの追加とみなす）
- リポジトリはコレクションとして振る舞い、ページネーションの詳細は `limit` に隠蔽する


## 7. ドメイン層の構成（ファイル構造）

```text
domain/
├── model/
│   ├── clip_item.go          // ClipItem エンティティ（集約ルート）
│   └── value_objects.go      // Content, ContentHash, ClipType, SourceApp, Timestamp ...
├── factory/
│   └── clip_item_factory.go  // NewClipItem(): 生成の唯一の経路
└──── repository/
    └── clip_item_repository.go  // ClipItemRepository インターフェースのみ
```

**依存ルール**: `domain/` パッケージは外部パッケージを一切 import しない。
インフラ・Wails・SQLite・OS API への依存は許容しない。
