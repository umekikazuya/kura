# 04. テスト仕様書

## 1. 単体テスト (Unit Test)

- 除外リスト検証: パスワードマネージャーのBundle IDを設定した際、クリップボードデータが保存処理（Repository層）に到達しないことを検証する。
- 重複更新検証: 既存と同一ハッシュのテキストが流入した際、レコードが新規作成されず、既存行のタイムスタンプのみ更新されることを検証する。

## 2. 結合テスト (Integration Test)

- FTS同期検証: `clips` テーブルへのCRUD操作時、トリガー経由で `clips_fts` テーブルのインデックスが正しく更新されることを検証する。
- IPC連携検証: フロントエンドからの検索クエリ送信時、Go側のメソッドが正しくディスパッチされ、JSON形式のDTOが返却されることを検証する。

## 3. 性能テスト・非機能テスト (Performance Test)

- 負荷テスト: 10万件のダミーデータをDBに投入し、`go test -bench` にてあいまい検索のレイテンシが10ms以内であることを検証する。
- 並行処理テスト: `go test -race` を実行し、監視Goroutineと検索Goroutine間のデータ競合（Data Race）がないことを検証する。
- リソース監視: 連続コピー処理後に、ガベージコレクションによってヒープメモリが基準値に戻ること（メモリリークの不在）を検証する。
