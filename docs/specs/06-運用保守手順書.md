# 06.運用保守手順書

## 1. 定常運用・保守計画

アプリケーションのパフォーマンス低下を防ぐための自動メンテナンスを定義する。

- データベース最適化: 起動時、前回の最適化から7日以上経過している場合、非同期でSQLiteの `VACUUM` または `PRAGMA optimize` を実行する。
- データパージ: 30日（設定で変更可能）以上経過した非ピン留め（`is_pinned=0`）のレコードおよび画像ファイルを自動的に物理削除する。

## 2. 障害対応・トラブルシューティング

ログの確認: 異常系エラーは `~/Library/Logs/kura/app.jsonl` に構造化ログ（slog）として出力される。

- 強制終了手順: アプリケーションがハングアップした場合、アクティビティモニタまたは `killall kura` コマンドでプロセスを終了する（常駐型のためOS再起動より早い）。
- データ破損時の復旧: データベースファイル (`data.db`) が破損し起動不可となった場合、対象ファイルを物理削除することで次回起動時に初期化処理を走らせる。

## 3. バージョンアップ手順

アプリケーションのスキーマ変更が伴うアップデートの場合、Goの `golang-migrate` 等のツールを用いて、起動時の初期化シーケンスでDBマイグレーションを自動実行する。
