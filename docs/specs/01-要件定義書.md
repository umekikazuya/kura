# 01. 要件定義書

## 1. プロダクトビジョンと目的

- 目的: 開発者のコンテキストスイッチを極限まで削減し、思考プロセスとシームレスに統合されるクリップボード管理体験を提供する。
- コンセプト: GUIの視認性とTUI（Vimライク）の高速なキーボード操作を融合させた、プロフェッショナル向けクリップボードマネージャー。

## 2. コア機能要件

1. 完全イベント駆動のバックグラウンド監視: OSのクリップボード変更イベント（`NSPasteboard` の `changeCount` 更新）をフックし、履歴として保存。
2. 超高速FTS検索・自動ペースト: グローバルショートカット（`Cmd + Option + V`）での瞬時起動、FTS5（Full-Text Search）を用いた日本語対応の高速ファジィ検索、および直前のアクティブウィンドウへの `CGEvent` 発行による自動ペースト。
3. データ永続化と保護: 任意アイテムのピン留め機能。
4. ハードウェアレベルのセキュリティフィルター: パスワードマネージャー（1Password, Bitwarden等）や、OS側で `org.nspasteboard.ConcealedType`（機密フラグ）が付与されたペーストボードアイテムの完全な記録バイパス。

## 3. 非機能要件（定量・システム制約・SLO）

### パフォーマンスとリソース管理 (P99目標)

- ウィンドウ描画レイテンシ: ショートカット押下から **32ms以内（2フレーム以内）**。
- 検索応答速度: 10万件のデータに対し、クエリ入力からDOM更新完了まで **16ms（60fps）**以内。
- メモリ消費: アイドル待機時のResident Set Size (RSS) **30MB**以下。
- CPU使用率: 監視待機時の負荷を最小限に抑える（ポーリングの場合は間隔を適切に制御し、CPUリソースの浪費を防ぐ）。

### ペイロード制限とメモリ保護

- 1回のコピーにつきテキストは最大5MB、画像は最大20MBまで。
- 超過分はストリーム処理にて切り詰め（Truncate）を行い、OOM (Out of Memory) を防ぐ。

### データプライバシー

ネットワーク通信を一切行わず、ローカルのSQLite（WALモード）のみで完結。

## 4. ターゲット環境（制約）

- Architecture: Apple Silicon (ARM64) 専業。
- Intel (x86_64) アーキテクチャはサポート対象外とし、Rosetta 2環境での動作も保証しない。
- OS: macOS 13 (Ventura) 以降。
